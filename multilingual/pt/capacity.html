Contexto




Durante minha graduação em Engenharia Elétrica pela PUCPR, participei de um processo selectivo buscando Trainees para a até então pequena e promissora GVT, que ostentava um EBITDA de 40% ao Ano.

O processo foi rigoroso, 300 candidados das principais universidades de Curitiba (PUC, Federal, Utfpr, UniBrasil) disputando 10 vagas, realizando em 3 etapas com prova Escrita, Dinamica e Entrevista fui um dos selecionados.

Nesse programa éramos nomeados EDUTECS, faziamos Job Rotation a cada 4 meses entre áres de Operações e Engenharia, o objetivo era dar experiência e fazer contatos nas múltiplas áreas que compoem uma operadora.

No fim do meu terceiro ciclo, apos 1 ano e 2 meses, meu interesse e minha habilidade com scripts gerou a efetivação na área de Engenharia de Dados como Analista JR, visto que minha graduação ainda estava em Curso.

Durante quase 10 anos, entre Agosto de 2009 a Novembro de 2018, vi e colaborei ativamente para a empresa ser o provedor premiado como melhor internet do Brasil, a ferramenta desenvolvida Capacity Plan, foi um facilitador.

Desafio

A empresa utilizava o software livre Cacti para monitorar o tráfego das interfaces, robusto, é uma ferramenta de rede para armazenamento de dados e apresentação gráfica, utiliza o poder do RRDTool (Round Robin Database).



Ótimo para a coleta dos dados, mas, péssimo na apresentação e geração de relatórios, aqui entra o Capacity Plan.



Capacity Plan

Hardware

O sistema foi criado utilizando um computador ocioso da área, com processor Intel i3 e 4GB de memória. Mais que suficiente para rodar os scripts e servir a página web com os resultados das coletas e análises.

Backend

Optei pelo conjunto LAMP (Linux Debian 8, Apache 2, MySQL, PHP 5). Juntos, eles oferece um conjunto comprovado de software para desenvolver aplicativos web de alto desempenho.

Frontend

Utilizando o Boostrap como framework pelo seu design "clean". O foco estava na aprentação gráfica dos dados. Aqui precisavamos de uma ferramenta poderosa, um colega de área (Alexandre Guedes) me indiciou o HighCharts.

Método

Acesso

O Servidor recebeu endereço ip estático dentro da rede MGMT (gerência) dos equipamentos por questões de segurança e rastreabilidade, os acessos aos equipamentos eram utilizando login/senha pessoais.

a idéia era apresentar o foi montado um servidor web Apache, com endereçamento da rede de gerência, e dentro das Polices de segurança dos equipamentos.

Todo dia as 5h da manha os scripts acessavam todos os equipamentos da Rede IP, coletava todas as informacoes desejadas (Interfaces, Capacidade, Descrições, Placas instaladas, Portas Livres) e populava o MySQL.

A operadora utilizava o sistema opensource cricket para registrar o tráfego, tal sistema nao tinha informacao de capacidade da interface, aqui entra a função do Capacity Plan.

Cruzando as informações coletadas dos equipamentos com o sistema cricket, demos vida aos dados. A base de dados mysql deu flexibilidade para organizar e agrupar as informações.

Os dados eram apresentados utilizando a biblioteca HighCharts em JavaScript e PHP como pode ser visualizado acima, dentro da base haviam relatórios semanais e histórico de crescimento utilizado para projeção de tráfego.
